# 데이터베이스 및 큐레이션 점수 전략

최종 업데이트: 2026-11-13
상태: **설계 초안** — 현재는 데이터 소스와 점수 구조를 제안하는 문서이며, 가중치와 채택할 외부 소스는 검증 후 확정합니다.

## 1. 목표

matdoria는 리뷰를 직접 받거나 자체 별점을 매기는 서비스가 아니다. 외부에 이미 존재하는 **전문가·기관 선정, 대중 평가, 업력, 가격·위생 같은 정량 신호**를 수집 가능한 범위에서 모아, 사용자가 정한 기준으로 여러 맛집 리스트를 만드는 프로젝트다.

점수는 식당의 객관적·절대적 맛 점수가 아니라, **선택한 데이터와 가중치에 따른 matdoria 큐레이션 점수**다. 따라서 점수 옆에 근거와 출처를 표시하고, 서로 의미가 다른 신호는 가능한 한 분리한다.

## 2. 구축 원칙

1. **먼저 권리와 수집 방법을 확인한다.** 공식 API, 공개 파일, 재사용 조건이 확인된 자료를 우선한다. 웹페이지 스크래핑이나 제3자 데이터셋은 출처·약관·갱신 이력이 불명확하면 점수 입력으로 쓰지 않는다.
2. **식당을 먼저 통합하고, 출처 기록을 보존한다.** 한 식당이 여러 목록에 나오더라도 canonical 식당은 하나로 두고, 각 출처의 기록은 따로 남긴다.
3. **원본과 파생 점수를 분리한다.** 원본 데이터, 식당 매칭 결과, 계산된 지표, 프로필별 점수를 서로 다른 산출물로 관리한다.
4. **미등재와 낮은 평가를 구분한다.** 특정 가이드에 없다는 이유로 감점하지 않는다. 미수집·미확인 값은 0점이나 부정 평가로 취급하지 않는다.
5. **하나의 만능 점수보다 여러 리스트를 지원한다.** 예: `전문가 선정`, `오래된 식당`, `가성비`, `종합 큐레이션`. 신호의 의미가 다른 경우 별도 필터나 프로필로 표현한다.
6. **매칭 신뢰도와 데이터 기준일을 추적한다.** 같은 건물의 다른 식당에 잘못 연결되거나 폐업 정보가 오래된 문제를 점수 신뢰도에 반영한다.

## 3. 권장 데이터 구조

현재 MVP는 CSV와 정적 JSON으로 충분하다. 논리적으로는 아래 테이블에 해당하도록 분리하고, 규모가 커지면 SQLite로 옮길 수 있게 설계한다.

### `places` — 통합 식당

식당당 한 행. `place_id`(카카오 장소 ID), 표시명, 주소, 좌표, 카카오 URL, 영업 상태를 둔다. 현재 프로젝트의 기준 키는 카카오 장소 ID다.

### `source_records` — 출처별 주장/평가

출처의 값을 식당 테이블에 덮어쓰지 않고, 식당-출처 조합마다 기록한다.

권장 필드:

- `place_id`, `source_id`, `source_record_id`
- `signal_type`: `guide_award`, `public_designation`, `rating`, `rating_count`, `operating_year`, `price`, `hygiene` 등
- `signal_value`, `category` (예: 미쉐린 1스타, 빕 구르망)
- `source_url`, `source_snapshot`, `source_updated_at`, `collected_at`
- `match_method`, `match_confidence`, `verification_status`
- `license_status`, `notes`

### `source_snapshots` — 수집 이력

소스 URL/식별자, 내려받은 시각, 데이터 기준일, 버전·커밋, 파일 해시, 행 수, 이용 조건, 수집 결과를 기록한다. 원본이 갱신돼도 이전 버전과 점수 산출을 재현할 수 있게 한다.

### `score_profiles` — 점수 설정

가중치와 변환 규칙을 YAML/JSON으로 버전 관리한다. 프로필마다 대상 범위, 포함 신호, 점수 변환, 결측 처리, 기준일을 명시한다. 현재 Matdoria's Pick 설정 초안은 `data/curation/matdoria_pick.json`이며, `sourceWeights`, 미쉐린 등급별 점수, 서울미래유산 유형별 점수, 최소 점수, 수동 포함/제외 ID를 둔다. 기본 가중치는 모두 0이고 최소 점수는 미설정이므로, 아직 어떤 식당도 자동 선택하지 않는다.

### `score_results` — 재현 가능한 결과

`place_id`, `profile_id`, `profile_version`, `total_score`, 신호별 점수, 데이터 커버리지, 계산 시각을 저장한다. UI에는 총점만이 아니라 점수 근거도 내보낸다.

## 4. 점수 산정 방식

### 4.1 프로필 단위 가중 합

처음에는 설명 가능한 규칙 기반 점수로 시작한다.

```text
profile_score(place) = Σ weight(signal) × transform(signal_value)
```

예를 들어 `critic_pick`은 가이드 등급을 중심으로, `long_running`은 확인된 운영 기간을 중심으로 계산한다. 변환과 가중치는 프로필 설정으로 관리하고, 코드에 상수를 흩뿌리지 않는다.

### 4.2 후보 신호별 처리

- **미쉐린 등급:** 등급을 순서형 범주로 변환한다. 별점·빕 구르망·셀렉티드의 점수 간격은 사실이 아니라 matdoria의 선호 설정이므로 버전과 근거를 남긴다.
- **블루리본·서울미식 등 가이드 목록:** 데이터와 재사용 권리가 확인된 경우에만 포함한다. 목록의 등급 체계가 있으면 등급을 보존하고, 단순 선정 여부는 별도 binary 신호로 둔다.
- **서울미래유산:** 개별 음식점, 음식골목, 후보를 분리한다. 음식골목 지정은 그 골목 안의 모든 식당에 자동 부여하지 않는다.
- **운영 기간:** 확인된 개업연도만 사용한다. 인허가일 등 간접 추정치는 `estimated`와 신뢰도를 표시하고, 확인값과 같은 점수를 주지 않는다.
- **착한가격업소:** 맛 점수가 아니라 가성비 프로필의 선정 신호 또는 필터로 사용한다. 공공 지정의 정확한 의미를 UI에도 표시한다.
- **모범음식점·위생등급:** 맛 평가가 아니라 위생/공공 지정 신호다. 종합 맛 점수에서 높은 가중치로 취급하지 말고 별도 필터 또는 약한 보조 신호로 둔다.
- **플랫폼 별점:** 플랫폼의 평균 점수와 평가 수는 서로 다른 필드다. 약관이 점수 계산·저장·표시를 허용하는지 확인되기 전에는 수집하거나 파생 점수에 넣지 않는다.

### 4.3 결측값과 데이터 커버리지

`미쉐린 등재 없음`은 `미쉐린에서 낮은 점수`가 아니다. 결측값에는 감점을 주지 않고, 점수 근거가 부족한 경우 `coverage` 또는 `evidence_count`를 함께 표시한다. 특정 소스의 대상이 아닌 식당은 해당 지표의 분모에서 빼고, 프로필 정의에서 그 처리를 명시한다.

### 4.4 검증 방법

1. 후보 식당과 신호가 확보된 비율을 먼저 계산한다.
2. 가중치 후보별 상위 목록과 점수 근거를 CSV로 출력한다.
3. 상위·중간·경계 식당을 표본 확인하고 오매칭·중복 선정·폐업을 기록한다.
4. 가중치를 바꿨을 때 순위가 얼마나 달라지는지 비교한다.
5. 표본 검토 후 프로필 버전을 고정해 export한다.

점수는 사용자 선호를 수치화한 것이므로, 검증의 목적은 실제 맛의 정답을 증명하는 것이 아니라 **계산의 재현성, 출처 정확성, 의도한 큐레이션과의 일치**를 확인하는 것이다.

## 6. 첫 구현 범위 제안

1. 기존 Michelin 및 서울미래유산 레코드를 `source_records` 구조에 맞게 정리한다.
2. 착한가격업소 CSV는 다운로드 및 서울 외식업 필터까지 확인했다. 다음으로 음식점 후보 분류와 주소 기반 식당 매칭을 구현·검증한다.
3. 모범음식점 파일은 공식 다운로드 경로 접근 문제를 해결한 뒤, 실제 컬럼·서울 커버리지를 평가한다.
4. 첫 점수 프로필은 `guide_curated`와 `value`를 분리한다. 점수와 함께 출처별 근거를 반환한다.
5. 블루리본·서울미식 100선은 권리/공식 데이터 형태 확인 전까지 수집하지 않는다.
6. Kakao/Google 평점은 batch로 수집해 `places.json` snapshot으로 표시한다. 업데이트 시각을 함께 보관하고, 일반 웹 페이지 로드/상세 열기에서는 외부 평점 API를 호출하지 않는다. Matdoria's Pick 점수에는 평점을 반영하지 않는다 (D-032).

웹앱에는 외부 목록별 탭과 `Matdoria's Pick` 탭을 구현했다. 현재는 미쉐린/서울미래유산만 매칭된 장소가 있으므로 나머지 탭은 0건과 준비 상태를 보여준다. 착한가격업소 원본 파일은 보관했지만 주소 검증을 통과한 연결 장소는 아직 없다.

실제 데이터 검증을 마친 뒤 `docs/data-sources.md`와 이 문서의 상태를 갱신하고, 최종 가중치 결정만 `docs/decisions.md`에 기록한다.
