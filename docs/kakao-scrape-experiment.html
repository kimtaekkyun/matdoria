카카오맵 장소 페이지 동작 원리 - 실험 기록

목적: 카카오맵 장소 상세 페이지가 별점과 리뷰 수를 어떻게 불러오는지 원리를 확인한다.
결론 요약: 페이지 HTML은 빈 껍데기이고, JavaScript 번들이 내부 API를 호출해 데이터를 채운다. 별점 필드(score_set.average_score)가 번들 안에 존재함을 확인했다. 다만 실제로 응답을 받은 호출은 없다. 추정한 엔드포인트 5개는 모두 404였다.
실험 범위: 운영용 수집이 아니며, 결과 데이터를 저장하거나 쓰지 않았다.

1. 실험 대상

테스트 장소: 7th Door (Kakao place ID 1147571189, data/processed/places_matched.csv에서 확인).

장소 URL: http://place.map.kakao.com/1147571189

3. HTML에서 본 것

1번 응답(장소 페이지 HTML, 3.5KB)의 구성은 다음과 같다.

  • 별점, 리뷰 수, 주소 같은 실제 데이터는 없다. 제목이나 본문 텍스트도 거의 없다.
  • <script> 태그 여러 개: 광고 추적(ba.min.js), 분석(tiara-1.2.0.min.js), 메인 번들(place_new/prod/931a016/index.js).
  • 레거시 브라우저용 index-legacy.js와 polyfills-legacy.js도 있다(nomodule).
  • 앱이 마운트될 <div id="app"> 같은 빈 컨테이너가 있을 것으로 보인다(Vue 앱 구조).

즉, 브라우저가 이 HTML을 받은 뒤 스크립트를 실행하면서 데이터를 가져와 화면을 그린다.

4. JavaScript 번들에서 찾은 것

메인 번들(index.js)과 청크 13개를 검색해 찾은 내용이다.

4-1. 장소 ID를 얻는 방법

function Ye(){return location.pathname.split("/").pop()}

URL 마지막 경로가 장소 ID다. 따라서 API 호출에 쓰이는 ID는 URL의 1147571189와 같다.

4-2. 리뷰 API 경로 템플릿

청크 DXkrVZC3.js에서 다음 문자열 템플릿을 찾았다. Pt는 다른 모듈에서 가져온 기본 경로다.

uE = Pt + "/places/tab/reviews/kakaomap"
mE = Pt + "/places/reviews/kakaomap/meta"
vE = Pt + "/places/reviews/kakaomap/photos"
dE = Pt + "/places/tab/bookings"
hE = t => Pt + "/places/" + Ye() + ...
Dt = uE + "/" + Ye() + "?order=" + Ke + "&only_photo_review=" + dt ...
await qn(Dt)

의미: 리뷰 탭은 {Pt}/places/tab/reviews/kakaomap/{장소ID}?order=...&only_photo_review=...을 호출하고, 응답을 kakaomap_review 객체에 넣는다.

4-3. 별점 필드

d = p.value.score_set
... score_set.average_score   // 평균 별점
... score_set.review_count    // 리뷰 수

별점과 리뷰 수는 kakaomap_review.score_set 안에 있다. 이 필드는 리뷰 API 응답에 들어 있는 것으로 보인다. 다만 응답을 실제로 받지 못해 필드 위치는 번들 코드로 추정한 것이다.

4-4. 기본 경로 Pt의 출처 (추정)

import {A as Pt, ...} from "../index.js"

청크는 Pt를 메인 번들(index.js)에서 가져온다. 메인 번들의 export 목록에서 pf as A가 보였지만, pf가 isAndroid 같은 다른 변수와 이름이 겹쳐서 실제 값을 확정하지 못했다.

그 밖의 단서:

  • ve = "/api/places"가 쓰이는 곳이 있다(이벤트 카드, BpGOa4-s.js). 이 패턴으로 보면 Pt는 /api 같은 접두사일 가능성이 있다.
  • 그러나 요청 7번(/api/places/tab/reviews/kakaomap/{id})은 404였다. 접두사가 틀렸거나 필요한 쿼리 파라미터가 없을 수 있다.
  • 번들에 //place.map.kakao.com 상수(pr, At, Tt)가 있다. axios 인스턴스 ar, cr의 baseURL로 쓰인다. 이것이 Pt일 가능성도 있다.

5. 결론과 한계

  • 확인됨: 페이지는 빈 HTML이고, 데이터는 JavaScript가 내부 API에서 받아 채운다. 별점과 리뷰 수는 score_set 필드에 들어 있다.
  • 확인 안 됨: 실제 API 응답. 기본 경로(Pt)를 확정하지 못했고, 추정한 경로 5개는 모두 404였다.
  • 추가로 찾으려면 브라우저 개발자 도구의 Network 탭에서 실제 요청 URL을 확인하는 것이 가장 빠르다. 이번 실험에서는 Network 탭을 쓰지 않았다.
  • 약관상 자동 수집이 허용되는지는 확인하지 않았다. 이 실험 결과를 운영에 사용하지 않는다.

6. 재현 방법

1. 브라우저에서 http://place.map.kakao.com/1147571189 열기
2. 개발자 도구(F12) > Network > Fetch/XHR 필터
3. 페이지를 새로고침하고 "reviews" 또는 "kakaomap"이 들어간 요청 찾기
4. 요청 URL, 헤더, 응답 JSON에서 score_set 확인
