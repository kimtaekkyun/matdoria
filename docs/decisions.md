## D-001 · 2026-11-09 · 확정

- 미쉐린 영문명은 좌표 50m 이내 음식점 후보가 하나이거나, 가장 가까운 음식점이 15m 이내이면 채택한다.
- 한글 별칭은 `data/aliases/michelin.csv`에 넣고, 카카오 검색으로 확인된 것만 쓴다.

- 미쉐린 영문명 좌표 채택(coord_only)은 정밀도를 샘플로 검수해야 한다.

## D-017 · 2026-11-10 · 확정 (D-014, D-016의 검수 절차는 대체됨)
**검수 목록 없이 규칙으로만 매칭하고, 규칙별 신뢰도 등급을 붙인다.**
- 원인 정정: 초기 drop의 원인은 영문명이 아니라 스크립트 버그였다. 좌표 주변 음식점을 이름 없이 가져오지 않아서 후보가 빠졌다. 수정 후 카테고리 검색(좌표 300m, 최대 45건)을 사용한다.
- 규칙 (먼저 걸리는 것이 채택): 150m 이내 이름 유사도 0.35 이상 → 300m 이내 0.80 이상 → 서울 내 이름 일치 (1km) → 30m 이내 최근접 음식점
- 신뢰도: `name_*`와 `name_only`는 high, `nearest_food`는 medium
- 샘플 점검 (nearest_food 25건): 약 2/3 정답. 같은 건물 옆 가게가 붙는 오류가 있음. 좌표 거리만으로는 구분 불가
- 서울미래유산 좌표는 수 km 어긋날 수 있다 (예: 림스치킨 혜화점)
- 결과: 282건 중 매칭 262건 (high 94, medium 168), drop 20건 (drop 중 다수는 책, 가옥, 건물 등 음식이 아닌 항목)
- 개선 옵션 (미실행): 미쉐린 영문 주소의 번지 수와 카카오 도로명 번지를 대조해 medium을 high로 올리는 방식

## D-019 · 2026-11-10 · 확정 (웹앱)
**웹앱은 `web/`에 Next.js 15 (App Router, TypeScript)로 만든다. 정적 빌드, 수동 갱신.**
- 지도: 카카오맵 JavaScript SDK. 키는 `NEXT_PUBLIC_KAKAO_MAP_KEY` (`web/.env.local`, git 제외). 예시는 `web/.env.local.example`.
- 기능: 마커 표시, 목록 선택, 출처 필터(전체/미쉐린/서울미래유산), 이름·주소 검색, 선택 시 상세 패널, "카카오맵에서 보기" 버튼, 출처 링크.
- 반응형: 800px 이하에서 지도 위 · 목록 아래 배치, 상세는 하단 카드.
- import 경로는 상대 경로 사용 (`@/` 별칭이 빌드에서 동작하지 않아 제거함). TypeScript는 5.x 고정 (Next 15가 TS 7을 지원하지 않음).
- 데이터: `scripts/export_places.py` → `web/public/data/places.json`.

## D-022 · 2026-11-10 · 확인 (카카오 도메인 등록)
**카카오 JavaScript 키는 등록된 출처(포트 포함)에서만 SDK가 로드된다.** 확인 결과: `file://`에서는 로드되고, 등록되지 않은 `http://localhost:3300`에서는 실패하며, 등록된 `http://localhost:3000`에서는 성공함. Vercel 배포 주소는 배포 후 같은 방식으로 추가 등록해야 한다.
- 추가 확인: 같은 네트워크의 다른 기기에서 `http://192.168.1.200:3000`으로 접속하면 등록되지 않은 출처라 실패함. 외부 기기에서 테스트하려면 이 주소도 사이트 도메인에 추가해야 함 (IP가 바뀌면 다시 등록). 이 PC에서는 `localhost`로 접속하는 것이 가장 간단함.

## D-023 · 2026-11-10 · 확정 (주소 검증 매칭)
**좌표 근처 음식점 중 주소가 일치하는 곳을 high로 채택한다 (`address_verified`).**
- 방법: 소스 주소의 구(區)와 번지 숫자가 카카오 도로명 주소에 모두 들어 있는지 확인. 층수(`2F`, `3층`), 호수, 우편번호는 제외. 300m 이내 음식점 중 가장 가까운 것을 고른다.
- 결과: 미쉐린 180곳 중 154곳이 주소 검증으로 high가 됨 (기존 이름 기반 10곳 포함, 미쉐린 high 164곳). 웹앱 장소 234곳 (미쉐린 159, 서울미래유산 79).
- 한계: 호텔이나 쇼핑몰처럼 한 건물에 식당이 여럿이면 주소가 같아 다른 식당이 붙을 수 있다 (예: Toh Lim → 더그랜드롯데 내 다른 식당). 같은 건물 내 복수 식당은 이름으로만 구별 가능하므로 medium 수준의 위험이 남아 있다. 샘플 점검 기준 대부분 정확.
- `nearest_food` (좌표 30m 최근접)는 주소 정보가 없거나 검증되지 않은 경우의 마지막 수단으로 medium 유지. 현재 미쉐린 12곳이 해당.

## D-024 · 2026-11-10 · 확정 (영문 도로명주소 대조)
**미쉐린 영문 주소와 카카오 한글 도로명주소를 행정안전부 도로명주소 API(engAddr)로 영문 변환해서 비교한다 (`address_verified_en`, high).**

- 호출 위치: 이 PC의 파이프라인(`scripts/match_kakao.py`)에서만 호출한다. 웹앱 실행 중에는 호출하지 않는다. 키는 프로젝트 루트 `.env.local`의 `JUSO_API_KEY`에 두며 git에서 제외된다.

## D-030 · 2026-11-12 · 대체됨 (D-031; 로컬 범위만)
**Kakao와 Google 평점은 로컬 개발 환경에서만 상세 카드에 실시간 표시한다.**

- Google Place ID만 기존 검증된 매칭 자료에서 가져와 정적 JSON에 둔다. Google 평점·평가 수 값은 JSON/export에 저장하지 않는다.

- 사용자가 개인적으로 요청한 실험 범위다. 이를 공개 서비스에서 사용할 권리나 약관 적합성을 의미하지 않으며, 개인 사용도 약관 적용 예외라고 단정하지 않는다. 배포 전에는 현재 정책과 권한을 다시 확인한다.

## D-031 · 2026-11-12 · 대체됨 (D-032; 실시간 endpoint에서 static snapshot으로 전환)
**Kakao 내부 평점 및 Google Places 평점을 상세 패널에 표시하고, 공개 배포에서도 API route를 활성화한다.**
- 표기: `K Star 4.0 ★★★★★ (123)`, `G Star 4.0 ★★★★★ (123)`. 별 다섯 개는 항상 표시하고, 별점에 비례해 채움 색상을 적용한다.
- Kakao/Google Maps 외부 상세 페이지로 각각 이동하는 버튼을 제공한다.
- 조회는 장소 상세를 열 때 on-demand로 하고, rating/count 응답은 정적 JSON에 넣지 않으며 `Cache-Control: no-store`를 사용한다. Google Place ID만 허용된 목록에서 사용한다.
- 평점 API는 현재 `places.json`에 존재하는 Place ID만 허용하며, 같은 provider/place 단위로 짧은 인스턴스 내 요청 간격 제한을 둔다. Google API 키는 server-side `GOOGLE_PLACES_API_KEY`로만 설정하고 `NEXT_PUBLIC_` 환경변수로 노출하지 않는다.
- 공개 route를 켜면 제3자가 요청할 수 있고 Google API 비용/쿼터가 발생할 수 있다. Vercel 배포 전 Google Cloud에서 Places API 제한, 사용량 알림과 quota를 설정한다. 메모리 rate limit은 serverless 환경에서 전역 보장이 아니다.
- 사용자의 요청에 따라 배포 동작을 활성화한 것이며, Google/Kakao 정책상 사용 허가를 확인했다는 의미는 아니다. 약관 적합성 검토와 공개 운영 위험은 별도다. 평점은 Matdoria's Pick 점수에 넣지 않는다.
- 내부 API 조사 따라하기: `docs/kakao-rating-api-walkthrough.html`.
