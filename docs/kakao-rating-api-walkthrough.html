카카오맵 평점 내부 API 조사 — 따라 하기

기준 장소: 세븐스도어 (Kakao Place ID 1147571189)
조사일: 2026-11-12 · 실행 환경: Linux 터미널, Chromium headless, Python requests

주의 — 공식 API가 아닙니다. 이 문서는 카카오맵 웹앱이 자체적으로 호출하는 undocumented 내부 요청을 공부하기 위한 기록입니다. 경로·헤더·응답 형식은 예고 없이 바뀔 수 있습니다. 테스트 1건이 자동 수집이나 재배포 권한을 의미하지 않습니다. 대량 호출, 리뷰 본문 수집, 우회 인증은 하지 마세요. 실제 서비스 이용 조건은 카카오 정책/약관에서 별도로 확인해야 합니다.

1. 목표와 관찰 방법

장소 페이지 HTML에 평점이 직접 들어 있지 않아도, 브라우저가 JavaScript를 실행하면서 별도 API 응답을 받아 화면을 만들 수 있습니다. 먼저 장소 페이지의 실제 스크립트 번들을 찾고, 그 안에서 리뷰 API의 경로와 필드 이름을 조사합니다.

브라우저로 직접 따라가려면 장소 페이지를 열고 개발자 도구(F12) → Network → Fetch/XHR를 고른 뒤 리뷰 탭을 엽니다. 요청 중 places/tab/reviews/kakaomap가 있는 항목을 누르면 URL, Request Headers, Response를 확인할 수 있습니다.

2. 장소 페이지와 JavaScript 번들 확인

일반 HTTP 요청은 자동화 차단으로 403을 반환했지만 Chromium headless 브라우저는 페이지를 읽었습니다. 프로젝트 루트에서 다음을 실행합니다.

mkdir -p tmp/kakao-rating-study

chromium --headless --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --disable-blink-features=AutomationControlled \
  --user-agent='Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 Chrome/131.0.0.0 Safari/537.36' \
  --dump-dom 'https://place.map.kakao.com/1147571189' \
  > tmp/kakao-rating-study/place.html

# 이 페이지가 실제로 불러오는 버전 경로의 index.js 찾기
BUNDLE_URL=$(grep -oE 'https://t1\.kakaocdn\.net/kakaomapweb/place_new/prod/[^" ]+/index\.js' \
  tmp/kakao-rating-study/place.html | head -n1)
printf '%s\n' "$BUNDLE_URL"
curl -fsS "$BUNDLE_URL" -o tmp/kakao-rating-study/index.js

이번 조사에서 페이지 제목은 세븐스도어 | 카카오맵, 번들 버전은 1b964d7였습니다. 버전 문자열은 고정값이 아니므로 따라 할 때는 HTML에서 새로 찾습니다.

3. 코드 분할된 chunk에서 리뷰 코드를 찾기

메인 번들에서 chunk 이름을 뽑아 내려받고, 리뷰 경로와 별점 필드를 검색합니다.

BASE_URL="${BUNDLE_URL%/index.js}"
mkdir -p tmp/kakao-rating-study/js

for name in $(grep -oE '[A-Za-z0-9_-]{5,}\.js' tmp/kakao-rating-study/index.js | sort -u); do
  curl -fsS "$BASE_URL/js/$name" -o "tmp/kakao-rating-study/js/$name" || true
done

rg -n -C 1 'places/tab/reviews/kakaomap|score_set|average_score|review_count' \
  tmp/kakao-rating-study/js

이번 버전에서는 chunk BqePDPUy.js에서 다음 단서를 찾았습니다.

uE = "".concat(Pt, "/places/tab/reviews/kakaomap")

score_set.average_score

4. 단서에서 요청을 구성한 과정

  1. places/tab/reviews/kakaomap는 리뷰 탭 API 경로의 일부입니다.
  2. 호출 코드에서 마지막 경로에 현재 페이지의 장소 ID를 붙이는 것을 확인했습니다.
  3. 같은 코드에서 쿼리 이름은 order, only_photo_review임을 확인했습니다.
  4. order 값을 확인하려고 번들에서 jo.Recommended="RECOMMENDED", jo.Latest="LATEST"를 찾았습니다. 추측한 recent를 넣었을 때 서버는 HTTP 400 Invalid parameter를 반환했습니다. 그래서 번들에서 확인한 RECOMMENDED를 사용했습니다.
  5. CQscXMzR.js에서 기본 URL이 //place.map.kakao.com, 요청 헤더에 앱 버전 6.6.0과 플랫폼 PC가 들어가는 것을 확인했습니다.

5. 집계값만 조회해 보기

응답에는 리뷰 데이터도 들어오므로, 화면에 필요한 집계 두 필드만 골라 출력합니다. 아래 예시는 응답 전체를 파일에 저장하지 않습니다.

curl -fsS -G 'https://place.map.kakao.com/places/tab/reviews/kakaomap/1147571189' \
  -H 'Accept: application/json, text/plain, */*' \
  -H 'Referer: https://place.map.kakao.com/1147571189' \
  -H 'appVersion: 6.6.0' \
  -H 'pf: PC' \
  --data-urlencode 'order=RECOMMENDED' \
  --data-urlencode 'only_photo_review=false' \
| python -c 'import json,sys; d=json.load(sys.stdin); s=d.get("score_set", {}); print({"average_score": s.get("average_score"), "review_count": s.get("review_count")})'
이번 테스트의 축약 결과 
{'average_score': 4.2, 'review_count': 17}

UI 표기 형태: K Star 4.2 ★★★★★ (17). 별은 항상 다섯 개이며 평점 비율만 색으로 채웁니다.

6. 응답에서 눈여겨볼 점

필드/요소의미주의
score_set.average_score화면에 표시되는 평균 별점이 값 하나만으로 리뷰 수나 신뢰도를 판단할 수 없습니다.
score_set.review_count평점 집계에 연결된 리뷰 수화면에서 카운트와 함께 보여주는 이유입니다.
reviews개별 리뷰 등 추가 응답 데이터이번 앱 경로에서는 읽거나 저장하지 않습니다.
order리뷰 정렬 방식현재 번들에서 확인한 허용값은 RECOMMENDED와 LATEST입니다.
appVersion, pf웹앱이 보내는 내부 요청 헤더버전이 바뀌면 달라질 수 있어 고정 계약으로 보면 안 됩니다.

7. matdoria 코드에서의 현재 사용

  • 현재는 웹앱 상세 화면에서 이 비공개 API를 실시간 호출하지 않습니다. 조회 제한과 반복 API 사용을 피하기 위해 스냅샷 방식으로 바꿨습니다.
  • scripts/fetch_kakao_ratings.py가 places.json에 있는 Kakao Place ID별로 API를 요청하고 average_score, review_count만 data/processed/kakao_ratings.csv에 저장합니다.
  • 현재 결과는 Kakao 장소 243곳 중 236개 평점, 7개 평점 없음입니다. 개별 리뷰 내용은 저장하지 않습니다.
  • scripts/export_places.py가 평점 스냅샷을 places.json에 넣고, 상세와 리스트는 그 값을 K Star로 표시합니다. 별 다섯 개는 항상 보이고 채움 비율은 평점/5입니다.
  • 다시 갱신하려면 python scripts/fetch_kakao_ratings.py --refresh 후 python scripts/export_places.py를 실행합니다. 호출 결과가 static data가 되므로 수집 시점이 오래되면 다시 갱신해야 합니다.
  • 이는 공식 API나 사용 허가를 뜻하지 않습니다. 내부 경로/응답은 언제든 변경될 수 있고, 반복·대량 사용은 정책 위험을 높일 수 있습니다.

8. 중단해야 하는 경우

  • HTTP 400이면 order나 필수 쿼리 값이 바뀌었을 가능성을 확인합니다.
  • HTTP 403/429면 반복 호출하지 말고 페이지에서 실제 요청과 이용 조건을 다시 확인합니다.
  • 응답 키가 없어졌거나 새로 인증을 요구하면 인증 우회나 비공개 토큰 추출을 하지 않습니다.
  • 요청 실패를 피하려고 대량 반복, 프록시 회전, CAPTCHA 우회 등을 하지 않습니다.
  • 이 API는 공개 안정성 보장이 없습니다. 배포 및 지속 사용은 서비스 약관과 데이터 사용 권한을 별도 확인해야 합니다.
